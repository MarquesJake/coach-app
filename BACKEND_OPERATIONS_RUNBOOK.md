# Coach First Backend Operations

## Automated controls

- Every production migration workflow runs lint, TypeScript, unit/security tests and a production build before applying schema changes.
- Supabase migration history must match the files in `supabase/migrations`.
- Coach files use a reserved database row before storage accepts the object.
- Upload completion verifies the stored size and MIME type before the file enters analyst review.
- Club file access requires an active, unexpired grant and uses a 60-second signed URL.
- Production health runs hourly through GitHub Actions and can be run locally with `npm run verify:production`.

## Release sequence

1. Use expand-only migrations for new application contracts.
2. Run `npm run lint`, `npm run typecheck`, `npm test` and `npm run build`.
3. Apply and verify the migration before deploying code that depends on it.
4. Regenerate types with `npm run db:types`.
5. Deploy from `main`.
6. Run `npm run verify:production`.
7. Check Vercel runtime errors and Supabase security advisors.
8. Tag the verified commit.

## Storage operations

- `coach-private-materials` is private and currently capped at 100MB per file.
- Use direct TUS uploads for PDFs, PowerPoint files and video clips.
- Use a controlled HTTPS link for larger training or match videos until a dedicated private-video provider is selected.
- A `pending_upload` row means the browser stopped before verification finished.
- A `failed` row is retained as an audit record; the coach should submit the file again.
- Never release a file unless it is `uploaded`, `verified` and `available`.

## Account and invitation operations

- Club and coach access is invitation-only.
- Invitation links are single-use, email-bound and expire after seven days.
- Resend delivery requires both `RESEND_API_KEY` and `INVITATION_FROM_EMAIL` in Vercel.
- Until those variables exist, issue the invitation and share the generated link through an approved secure channel.
- Internal owner/admin accounts must use unique passwords and MFA.

## Dashboard-owned launch gates

These settings cannot be inferred or safely generated by application code:

- Enable Supabase leaked-password protection.
- Configure Supabase custom SMTP and verify the sending domain.
- Confirm daily backups and the required PITR plan in Supabase.
- Rotate any password that has been shared in chat or reused elsewhere.
- Add `SUPABASE_DB_PASSWORD` to GitHub Actions only if live rollback RLS tests should run automatically.

## Monthly recovery drill

1. Export the current migration list and confirm local/remote parity.
2. Confirm the latest database backup timestamp.
3. Upload a labelled test PDF through a coach identity.
4. Review and release it to a test club identity.
5. Confirm access, expiry, revocation and access-event logging.
6. Delete or quarantine the test material through the approved retention process.
